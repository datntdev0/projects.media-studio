# Backend (NestJS 11)

## Layering

One folder per feature, each file named for its job:

| File | Holds |
| --- | --- |
| `*.controller.ts` | HTTP only — route, validate, delegate |
| `*.manager.ts` | The rules. No request, no response |
| `*.repository.ts` | Firestore access |
| `dto/*.dto.ts` | The wire contract |
| `entities/*.entity.ts` | The stored shape |

Keep managers framework-free apart from DI, so their specs need no Nest fixture.
Shared plumbing goes in `src/core/`, never in a feature folder.

## DTOs drive the frontend

`nswag.json` generates one client class per `@ApiTags` value. So:

- Change a DTO, and the frontend client is stale. Rerun `pnpm generate:api`.
- A new `@ApiTags` value is a new client the frontend has to be given.

## Tests

Specs sit beside what they test as `*.spec.ts`, run by Jest.
Run one with `pnpm --filter @media-studio/backend run test -- <pattern>`.
